# Tests: strava-dashboard

## How to run
All commands from the repo root. Python 3.12 and Node 24 are required; there is no `uv` on the VPS.

- **Install**
  - Python: `python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'`
  - Web: `npm --prefix web ci`
  - Browser for Playwright (once per machine): `cd web && npx playwright install chromium`
    (CI uses `--with-deps`; the VPS already has chromium for Playwright 1.64)
- **Lint / format check / typecheck**
  - Python: `.venv/bin/ruff check .` · `.venv/bin/ruff format --check .` · `.venv/bin/mypy` (strict on `sdash/`)
  - Web: `npm --prefix web run lint` · `npm --prefix web run format:check` · `npm --prefix web run typecheck`
    (eslint and prettier cover `web/`, `tests/acceptance/web/` and `tests/screenshots/`; `tsc` checks them too)
- **Unit**
  - Python: `.venv/bin/pytest tests/unit`
  - Web: `npm --prefix web test` (vitest, `web/src/**/*.test.ts`)
- **Acceptance / e2e**
  - Pipeline (pytest, runs the `sdash` CLI as a subprocess): `.venv/bin/pytest tests/acceptance/pipeline`
    (the REQ-009 refresh tests need `web/node_modules`; they skip without it)
  - Web (Playwright against the built site): `npm --prefix web run test:acceptance`
    = copy `tests/acceptance/web/site-data` → `web/public/data`, `vite build`, `playwright test --project=acceptance`
    (`vite preview` on port 4318; override with `PW_PORT=...`)
  - Everything Python at once: `.venv/bin/pytest` (unit + pipeline acceptance)
- **Run not-yet-implemented tests anyway** (to see them fail, or to check your work before un-marking):
  - pytest: `.venv/bin/pytest --runxfail tests/acceptance/pipeline -k req004`
  - Playwright: `ACCEPTANCE_RUN_ALL=1 npm --prefix web run test:acceptance`
- **Raw-data check (REQ-010)**: `python3 scripts/check_raw_data.py`
- **Screenshots** (not a test): `npm --prefix web run screenshots` → `screenshots/<screen>-<viewport>-<scheme>.png`
  for every screen in docs/PLAN.md "Screens", mobile 390x844 + desktop 1280x800, light only (DESIGN.md is light only).
- **Mutation testing** (CI only, milestone PRs `chore/milestone-*`, report only): mutmut on `sdash/match.py`
  (`[tool.mutmut]` in pyproject.toml). Too heavy for the 4 GB VPS.

## CI (.github/workflows/)
- `ci.yml`, job **`ci`** (required check): raw-data check → install → ruff → ruff format --check → mypy → eslint →
  prettier --check → tsc → pytest unit → vitest → pytest acceptance (pipeline) → Playwright acceptance (web).
- `acceptance-guard.yml` (required check): PRs touching `tests/acceptance/` or `.github/workflows/` need a
  `test-review: success` status on the head SHA or Martin's `acceptance-change` label.
- `screenshots.yml` (not required): captures the screens as a run artifact.
- `mutation.yml` (not required, `continue-on-error`): mutmut report artifact on milestone PRs.

## Conventions
- **Not implemented yet = marked, never deleted or weakened.**
  - pytest: `@pytest.mark.xfail(strict=True, reason="REQ-00x not implemented (T-00y)")` (also `xfail_strict = true`
    in pyproject.toml). Strict means: when a test starts passing it is reported as `XPASS(strict)` = **failure**,
    so the task that makes it pass must remove that marker in the same PR (that PR touches tests/acceptance/,
    so it needs the test-reviewer).
  - Playwright: `fixme("REQ-00x: ...", ...)` from `tests/acceptance/web/helpers.ts` (= `test.fixme`, reported as
    skipped). The implementing task changes `fixme(` to `test(`.
  - Parametrized cases carry their own marks where tasks differ (e.g. REQ-002 formats: gpx = T-002, others = T-003).
- Names carry the REQ ID: pytest `test_req00x_...` plus `pytest.mark.req("REQ-00x")`; Playwright titles start
  with `REQ-00x:` and carry the tag `@REQ-00x` (`npx playwright test --grep @REQ-007`).
- **Synthetic data only.** Pipeline inputs are generated in the tests by `tests/acceptance/pipeline/_synth.py`
  (FIT encoder, StravaGPX-style GPX, TCX, gzip variants, Strava-style `activities.csv`, export zip with dummy
  personal files) and `_scenarios.py` (REQ-004 geometries). All tracks lie in the made-up area
  `SYNTH_BOX` (lat −48…−46, lon −136…−133, open South Pacific); `test_req010_fixture_tracks_lie_in_the_synthetic_area`
  enforces this for every track, `segments.csv` and zip member under `tests/fixtures/`. Never use anything from `~/data/strava-export/`.
- `test_synth_helpers.py` checks the builders themselves (FIT decodes with fitdecode, each REQ-004 scenario really
  meets/violates the rule it claims), so a failing acceptance test always points at the product.
- **No network.** URL import tests run a local HTTPS server on 127.0.0.1 with a throwaway CA made by the `openssl`
  CLI; deploy tests push to a local bare repo that refuses non-fast-forward pushes. The test env sets dead proxies
  (`http(s)_proxy=127.0.0.1:9`) so an accidental real request fails fast.
- `tests/acceptance/web/site-data/` (synthetic site JSON for the web tests, the web tests' oracle) is generated by
  `python3 tests/acceptance/web/make_site_data.py` (deterministic). It lives under tests/acceptance/ so the
  acceptance-guard protects it: changing it needs the test-reviewer, like any acceptance-test change.

## Contracts the acceptance tests rely on
These fill details the PRD leaves open. If an implementation needs a different contract, change it through the
test-reviewer (or a plan PR), not silently in code.

### CLI (`sdash`, all via the console script)
- Global `--data-dir DIR` (before the subcommand; default `$SDASH_DATA_DIR`, else `~/data/strava-export`).
  Errors: non-zero exit, message on stderr. Stubs print `not implemented`; acceptance tests treat that as a failure.
- `sdash import <zip|https-url>` → `DIR/raw/` holds `activities.csv`, `activities/…`, `segments.csv` (+ the other
  allowlisted CSVs), nothing else; a re-import replaces `raw/` contents. Non-https URLs fail before any connection
  and the message says https. Unsafe entries (`..`, absolute) fail and the message names the entry. Total
  uncompressed size (sum of entries, central directory) over 3 GB fails before anything is written; message
  mentions size/limit. Downloaded zips are deleted (also from `$TMPDIR`); the link (query string) never appears
  in output or `DIR/reports/`.
  - Host allowlist (production: `strava.com`, `amazonaws.com`) applies to the link's host **and to every redirect
    target**. Matching is exact host or dot-boundary suffix: `email.strava.com` matches `strava.com`,
    `evilstrava.com` does not.
  - Test-only hook `SDASH_ALLOWED_HOSTS` (comma-separated hosts): replaces **only the host list**. https-only,
    the size caps and the per-redirect host check still apply, matching stays exact/dot-boundary, and when it
    is set sdash prints a warning naming `SDASH_ALLOWED_HOSTS` on stderr. TLS trust in tests comes from
    `SSL_CERT_FILE` (also `REQUESTS_CA_BUNDLE`/`CURL_CA_BUNDLE`, whichever HTTP client is used).
- `sdash parse` → `DIR/cache/<activity id>.json.gz` = gzip JSON `{"t": [...epoch s], "lat": [...], "lon": [...],
  "d": [...cumulative m]}` for each Ride / E-Bike Ride only; records without a position are dropped. Cache key =
  source file size + mtime (same size+mtime → not re-parsed). A broken file does not stop the run (exit 0); its
  activity ID and a reason appear in the output or under `DIR/reports/`.
- `sdash match` → validates `DIR/segments.yaml`, errors name the segment and the problem (missing field name,
  "range"/"invalid", "duplicate").
- `sdash build-data --out OUT` (default `web/public/data`) → `index.json`, `segments/<slug>.json`,
  `rides/<id>.json` per ARCHITECTURE.md "Site JSON" (keys checked as a minimum set; extra keys allowed); only
  `.json` files; no coordinate keys (`lat`, `lon`, `start`, `end`, `points`, …) and no coordinate values;
  byte-identical on rebuild (so `generated` must come from the data, not the clock). Dates are UTC ISO 8601.
  `rides/<id>.json` exists for every cycling ride (also with no efforts). Effort objects in
  `segments/<slug>.json` carry at least `activity_id`, `start_t`, `elapsed_s`, `distance_m` (Effort model).
  Slug: lowercase ASCII words joined by `-` (`River path north` → `river-path-north`), independent of other segments.
- `sdash segment add --name N --activity ID --from-km A --to-km B` appends to `segments.yaml` with
  `ref_activity`, `start`/`end` = `[lat, lon]` at those distances (±15 m). `sdash segment import-strava` appends the
  rows of `DIR/raw/segments.csv` whose names are new, in file order. Invalid rows are reported on stderr with the
  row number and skipped; exit 0 if any row was added or all were existing, non-zero if some rows were invalid and
  nothing was added.
- `sdash deploy [--web-dir W] [--remote R]` → guard, then `W/dist` becomes a new commit on branch `gh-pages` of `R`
  (normal push, fast-forward; `main` untouched). Guard aborts (non-zero, names the file, nothing pushed) on any
  `.fit/.gpx/.tcx/.csv` file (+ `.gz`; every CSV, not only `activities.csv`) or JSON with coordinate keys.
- `sdash refresh [zip|url] [--no-deploy] [--web-dir W] [--remote R]` → import (if given) → parse → match →
  build-data into `W/public/data` → `npm run build` in `W` → deploy unless `--no-deploy`. Any failing step = non-zero (segment-level warnings are exit 2 and still deploy, Plan v3 / T-013)
  exit and nothing pushed. The report has a "parsed" line with a count, the failed activity IDs, and one line per
  segment with its name and effort count.

### Web UI (tests/acceptance/web)
- Built site at `/strava-dashboard/`, hash routes `#/`, `#/segment/<slug>`, `#/ride/<id>`; data fetched from
  `<base>data/…`. Browser runs in UTC, locale en-GB.
- Tables with accessible names (caption or `aria-labelledby` the panel heading): index **"Segments"**, **"Rides"**;
  segment page **"All efforts"**, **"By year"**; ride page **"Segments on this ride"**. Data rows in `<tbody>`.
- Formats from docs/DESIGN.md: times `m:ss` / `h:mm:ss`, dates `12 Jun 2024` (`Sep` or `Sept` accepted),
  km and km/h with one decimal, gap `+m:ss`.
- Segment page: rank in the first cell (`PR`, `2nd`, `3rd`, then numbers); sort buttons named Fastest/Newest
  (or containing "time"/"date"); chart = a `<canvas>` with `aria-label` containing `PR m:ss`, PR dot drawn in
  `#FC4C02`. Empty state: text containing "no efforts", no table, no canvas.
- Ride page: rank cell `5 / 8`; a PR mark is a cell text containing the word `PR` (e.g. "NEW PR"); empty state text
  containing "no segments matched", no table.
- Index: rides sorted newest first by the UI (the fixture JSON is deliberately unsorted); empty segment list
  shows text containing `sdash segment add`.
